# Обновление PPDB

## Новое изображение вместе с обновлением таблицы

Откройте Cloudflare Dashboard, затем R2 Object Storage и бакет `ppdb-media`.
Перейдите в `media/logos/`, нажмите Upload и загрузите оригинал. Например,
`uaSolidarnist.png` должен получить ключ `media/logos/uaSolidarnist.png`.
Если этих папок не видно, включите отображение префиксов как каталогов.
Файлы загружаются в R2; папка изображений в репозитории больше не используется.

В таблице в поле `LOGO` укажите `uaSolidarnist.png`. Имя должно совпадать с
загруженным файлом, включая регистр и расширение. Прямой URL изображения также
поддерживается и сохраняется как есть. Для `FORMER_LOGO` используйте тот же
принцип: одна строка на логотип, например `uaSolidarnist1.png||2020` или
`uaSolidarnist1.png|Под прежним названием|22-10-2017`.

Сохраните книгу под точным именем `PPDB database.xlsx` и замените файл в
[каталоге data](https://github.com/PLATELru/ppdb/tree/main/data). Названия вроде
`PPDB database(7).xlsx` автоматически не подхватываются. Загрузка файла
`PPDB database.xlsx` в корень по-прежнему поддерживается, но эта копия получает
приоритет над `data/PPDB database.xlsx`; обновлять нужно используемую копию.

После коммита действие
[Deploy PPDB to GitHub Pages](https://github.com/PLATELru/ppdb/actions/workflows/pages.yml)
проверит таблицу и обработку изображений. Оно создаст недостающие миниатюры в
R2 и опубликует GitHub Pages. В обычном запуске скачиваются только новые или
изменённые изображения. Если обработка не удалась, новая версия Pages не
публикуется; причина видна в журнале соответствующего шага.

## Загрузка или замена только изображения

Загрузите оригинал в `ppdb-media/media/logos/`. Затем откройте действие
[Update PPDB logo thumbnails](https://github.com/PLATELru/ppdb/actions/workflows/r2-media.yml),
нажмите Run workflow, выберите ветку `main` и запустите его. Флажок `verify_all`
для обычного обновления оставьте выключенным. Действие обновит миниатюры прямо
в R2, без добавления файлов или коммитов в репозиторий.

При замене под тем же именем адрес сохраняется, и браузер может показывать
предыдущую версию до одного часа. Для немедленной смены загрузите файл под
новым именем, например `uaSolidarnist2.png`, и обновите ссылку в таблице.
Миниатюры вручную создавать и загружать не требуется. При необходимости полной
проверки архива запустите это же действие с включённым `verify_all`.

## Основной сайт и GitHub Pages

GitHub Pages обновляется автоматически после изменения используемой таблицы
или кода. Основной сайт `ppdb-project.pltl27.chatgpt.site` публикуется отдельно.
После изменения таблицы или кода попросите синхронизировать основной сайт с
актуальным GitHub и опубликовать его. Такая публикация больше не требует
переноса архива логотипов. Замена изображения под уже используемым именем
обновляет изображение на обоих сайтах через R2 с учётом кэша.

## Хранение и прежние ссылки

Оригиналы находятся в R2 под `media/logos/`, миниатюры — под
`media/logo-thumbnails/logos/`. Настройки доступа к бакету остаются прежними;
публичный Worker выдаёт изображения через
`https://ppdb-media.tifmch.workers.dev`. Ключи доступа остаются в секретах
GitHub Actions и не добавляются в таблицу или код сайта.

При переносе каталога `atFPO.png` и `atFPO-alt.png` сохранены раздельно. Старый
путь `/media/logos3/atFPO.png` соответствует `atFPO-alt.png`. Прежние пути
`/media/logos/…`, `/media/logos2/…` и `/media/logos3/…` импортёр понимает.

Обработка не удаляет объекты из R2. Старые объекты с путями logos2 и logos3
сохранены для совместимости ранее опубликованных ссылок. Старые Git-коммиты и
резервные ветки также сохранены; обычное удаление файлов из `main` не очищает
содержимое истории Git.
