# Таблица и изображения

Актуальная таблица находится в `data/PPDB database.xlsx`. Заменяйте этот файл
через загрузку файлов GitHub в каталоге `data`. Если загрузить файл с именем
`PPDB database.xlsx` в корень репозитория, импортёр использует его с приоритетом
над копией в `data`; одновременно обновлять две копии не требуется.

Оригиналы изображений загружайте в одну папку `public/media/logos`.
В `LOGO` достаточно написать имя файла с расширением: `uaSolidarnist.png`,
`rsNPS.svg` или `rsNPS1.png`. Имя должно точно совпадать с загруженным файлом,
включая регистр. Можно указать прямой `https://...` URL изображения; такой URL
используется как есть. Пустое поле оставляет текстовое обозначение партии.

В `FORMER_LOGO` используется тот же способ указания файла. Каждая строка имеет
формат `имя-файла|комментарий|дата`. Например, `rsNPS1.png||22-10-2017`.
Старые значения `/media/logos/…`, `/media/logos2/…` и `/media/logos3/…`
поддерживаются и преобразуются в общий каталог.

При обновлении GitHub Actions импортирует таблицу. Если изменились изображения
или параметры миниатюр, он создаёт WebP-миниатюры, синхронизирует файлы с R2 и
проверяет их контрольные суммы. Только затем публикуется GitHub Pages.
Сохранённая контрольная сумма архива позволяет пропустить повторную загрузку,
если изменена одна таблица. Ручное действие `Sync PPDB media to R2` выполняет
принудительную проверку и подходит для восстановления удалённых объектов.
Основной сайт на Sites публикуется отдельно от GitHub Pages.

Исходные изображения сохраняются в GitHub, а публикуемые сборки получают их из
R2. Прямые внешние URL остаются на указанном внешнем сервере. Если локального
файла ещё нет, его имя сохраняется в таблице, а сайт показывает обозначение
партии до загрузки изображения.

При объединении каталогов два разных файла `atFPO.png` сохранены как
`atFPO.png` и `atFPO-alt.png`. Старый путь `/media/logos3/atFPO.png` соответствует
`atFPO-alt.png`. Старые объекты R2 не удаляются, поэтому ранее опубликованные
ссылки продолжают работать.
